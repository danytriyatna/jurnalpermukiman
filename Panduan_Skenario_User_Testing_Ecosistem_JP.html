Tahap Pengujian 1 • Alur Penulis & Integrasi Frontend

Uji Integrasi Widget OJS → Knowledge System JP-Insight

• Titik Integrasi: OJS Footer Script (Port 80) → JP-Insight API (Port 3001)

Widget chat melayang di kanan bawah portal OJS (#tanya-jp-widget) memanggil endpoint streaming http://localhost:3001/api/widget/chat secara asynchronous tanpa me-reload halaman OJS.

Langkah Aksi Pengujian (Instruksi untuk Anda):

  1. 1.1
    Buka portal utama OJS Jurnal Permukiman di browser:
    Buka OJS Homepage ↗ (Amati tombol floating bulat "Tanya JP" di pojok kanan bawah)
  2. 1.2
    Klik tombol "Tanya JP" hingga jendela chat popup terbuka.

    Ketikkan pertanyaan riset berikut (atau klik tombol salin):

    Bagaimana efektivitas teknologi RISHA untuk perumahan pasca bencana menurut arsip Puskim?
  3. 1.3
    Verifikasi Hasil yang Diharapkan (Expected Result):
    • AI memberikan jawaban sintesis berbasis korpus Puskim tanpa halusinasi.
    • Muncul nomor sitasi atau kartu referensi artikel jurnal terkait di bagian bawah respons.
    • Tidak terjadi error CORS pada konsol DevTools browser (F12).
02
Tahap Pengujian 2 • Alur Penulis & Screening Engine

Uji Quality Gatekeeper: Audit Naskah di MQC Assistant

• Titik Integrasi: OJS Navigation → MQC Frontend (:3000) → Screening Engine (/api/check-submission)

Penulis menguji kepatuhan naskah (.docx) sebelum menyerahkan ke OJS. Engine MQC memeriksa 25 parameter selingkung (Font, Margin, Abstrak dwibahasa, Judul Tabel/Gambar, Format Sitasi IEEE/APA) dan menerbitkan skor kelayakan.

Langkah Aksi Pengujian:

  1. 2.1
    Buka halaman Dashboard atau Upload Naskah MQC Assistant:
    Buka Dashboard MQC ↗ Buka Upload Naskah ↗
  2. 2.2
    Uji Verifikasi Hasil Simulasi Audit (Passed vs Needs Revision):

    Di Dashboard MQC, klik kartu audit naskah yang berstatus Passed (Skor 92) dan naskah berstatus Needs Revision (Skor 68).

  3. 2.3
    Verifikasi Hasil yang Diharapkan (Expected Result):
    • Naskah lolos menunjukkan rincian 25 kriteria checklist gaya selingkung berwarna hijau.
    • Naskah belum lolos menampilkan daftar pelanggaran spesifik (misal: "Ukuran font sub-bab tidak 11pt", "Abstrak bahasa Inggris belum ada").
    • Penulis diarahkan untuk memperbaiki berkas naskah sebelum menekan tombol lanjut ke OJS.
03
Tahap Pengujian 3 • Alur Redaksi & Sistem Inti OJS

Uji Penyerahan Naskah (Submission) & Editorial OJS 3.3

• Titik Integrasi: Author Submission → OJS 3.3 Backend Workflow (:80/submissions)

Naskah yang telah dinyatakan lolos screening MQC diserahkan ke OJS melalui antarmuka formal 5 langkah. Dewan redaksi (Editor) menerima naskah di antrian Submissions untuk diteruskan ke tahap Peer Review substantif.

Langkah Aksi Pengujian:

  1. 3.1
    Buka antarmuka Submissions OJS Jurnal Permukiman:
    Buka OJS Submissions ↗ (Atau klik tombol "Make a Submission" pada homepage OJS)
  2. 3.2
    Uji Alur Wizard Penyerahan 5 Langkah:

    Klik "New Submission" → Centang Submission Checklist → Unggah berkas naskah .docx → Isi metadata (Judul & Abstrak) → Konfirmasi & Kirim.

  3. 3.3
    Verifikasi Hasil yang Diharapkan (Expected Result):
    • Naskah masuk antrian My Queue / Unassigned editor OJS dengan ID submission baru.
    • Redaksi tidak lagi membuang waktu menolak naskah akibat format font/margin yang salah karena sudah tersaring di Gate 2.
    • Editor dapat langsung menugaskan Section Editor dan Mitra Bestari (Reviewer).

Tahap Pengujian 4 • Siklus Tertutup (Closed-Loop)

Uji Auto-Harvest OAI-PMH: OJS 3.3 → JP-Insight RAG Engine

• Titik Integrasi: OJS OAI-PMH Endpoint (Port 80) → JP-Insight Harvester Engine (:3001/api/sync/ojs)

Inilah inti integrasi siklus tertutup. Ketika naskah terbit di OJS, metadata dan berkas artikel otomatis diekspos melalui protokol internasional OAI-PMH.
