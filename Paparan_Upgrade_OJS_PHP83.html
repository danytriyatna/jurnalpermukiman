Latar Belakang Paparan Laporan Awal

Jurnal Permukiman merupakan media publikasi berkala ilmiah resmi di lingkungan Kementerian PUPR. Guna memenuhi standar keamanan server pusat data pemerintah, menjaga kelancaran publikasi ilmiah, serta mengoptimalkan layanan kepada peneliti dan dewan redaksi, diperlukan modernisasi runtime PHP 8.3 dan penyelarasan menyeluruh dengan modul pengecekan format naskah (MQC) serta pusat referensi (JP-Insight).

Peningkatan Versi PHP Jurnal Permukiman & OJS

Server pusat data mewajibkan penggunaan versi runtime aktif yang didukung pembaruan keamanan resmi. PHP 8.1 telah habis masa dukungannya sehingga wajib beralih ke PHP 8.3.

Laporan Audit Teknis Repositori Pemeriksaan Kode & Kesiapan Repositori Serah-Terima (Tahap 2, 3, & 4 KAK)

Hasil Audit Teknis & Pembenahan 3 Repositori (Sebelum vs Sesudah)

Laporan objektif kondisi kode repositori saat diserahterimakan kepada konsultan dibanding tindakan teknis perbaikan yang telah dilaksanakan, lengkap dengan dasar bukti fisik repositori:

01. Repositori OJS Core ✅ Audit & Upgrade Selesai
🔴 Kondisi Awal Kode (Saat Serah Terima)
  • Basis Kode Versi Lama: Repositori berada pada rilis 3.3.0.13 (Oktober 2022) yang belum memuat perbaikan keamanan PKP terkini.
  • Inkompatibilitas PHP 8.3: Pustaka bawaan (Smarty 3 & ADOdb 5) memicu ribuan pesan peringatan error saat diuji pada server PHP 8.3.
  • Ketergantungan Aset Pihak Ketiga: Berkas tema styleSheet.css memuat tautan gambar latar ke domain eksternal publik (i.ibb.co) yang rawan broken link, serta belum tersedia bilah akses cepat ke aplikasi ekosistem.
🟢 Tindakan Teknis Konsultan (Hasil Perbaikan)
  • Pembaruan ke Rilis LTS Resmi: Basis kode berhasil ditingkatkan ke versi resmi PKP 3.3.0-24 LTS yang teruji stabil dan aman.
  • Penambalan Pustaka Usang: Pustaka internal telah dipatch penuh; sistem beroperasi 100% bebas error pada stack PHP 8.3.30 + MySQL 8.4.3.
  • Lokalisasi Aset & Integrasi Navigasi: Seluruh aset tampilan dilokalisasi ke server internal, palet warna heritage Puskim (#c13d0d) distandarisasi, dan tombol akses cepat ekosistem disematkan rapi 1 baris.
🔍 Dasar Bukti Fisik Repositori & DB:
• Versi 3.3.0.13: dbscripts/xml/version.xml, docs/README.md, dan record DB versions (11-05-2023).
• PHP Awal: lib/pkp/composer.json terkunci pada platform php: 7.3.0; server lama PHP 7.3 - 8.0.
• PHP Target: Mandat KAK Pekerjaan 1 (Peningkatan ke PHP 8.3); teruji di PHP 8.3.30.
• Aset Tema: public/journals/1/styleSheet.css (lokalisasi aset gambar eksternal & penataan navigasi).
Hasil Audit Kode: STABIL & SIAP INTEGRASI
02. Repositori MQC Assistant ✅ Audit Kode Selesai
🔴 Kondisi Awal Kode (Saat Serah Terima)
  • Bug Pembacaan XML Dokumen: Penanganan tag kotak teks ganda Word (mc:Choice vs mc:Fallback) membuat judul tabel/gambar terhitung dobel.
  • Inkonsistensi Definisi Aturan: Konstanta pada kode mencatat 27 aturan, sementara berkas katalog definisi baru memuat 22 aturan.
  • Kesiapan Antarmuka Pemanggilan: Belum ada mekanisme pengujian endpoint lokal terstandar untuk menerima kiriman berkas dari OJS.
🟢 Tindakan Teknis Konsultan (Hasil Perbaikan)
  • Koreksi Logika Parser Word: Pembacaan struktur XML dokumen diperbaiki menggunakan metode penelusuran hierarki agar hitungan objek akurat.
  • Sinkronisasi Katalog Aturan: Kode katalog diselaraskan menjadi 25 kriteria gaya selingkung terverifikasi tanpa inkonsistensi.
  • Verifikasi Kesiapan Endpoint: Jalur penerimaan berkas (API /api/check-submission) teruji aktif dan siap dipanggil di server dev.
🔍 Dasar Bukti Fisik Repositori:
• Parser Word: src/lib/docx.ts (penanganan DrawingML Word dan eliminasi bug hitung ganda).
• Katalog Aturan: src/lib/constants.ts vs src/lib/rules.ts (standarisasi 25 kriteria gaya selingkung).
• Endpoint API: src/app/api/check-submission/route.ts aktif di port 3000.
Hasil Audit Kode: TERKALIBRASI & SIAP INTEGRASI
03. Repositori JP-Insight ✅ Audit Data & Pemanen Selesai
🔴 Kondisi Awal Kode (Saat Serah Terima)
  • Ketergantungan Layanan Cloud: Repositori masih bergantung langsung pada basis data cloud tanpa konfigurasi simulator lokal untuk pengujian dev.
  • Validasi Skrip Penyerapan Data: Modul pemanen data (lib/ojs.ts) belum tervalidasi terhadap endpoint penyedia metadata OJS lokal.

  • Uji Konektivitas Pemanen Data: Skrip pembaca XML teruji sukses terhubung ke endpoint protokol OAI-PMH milik OJS.
  • Verifikasi Integritas Korpus: Seluruh 210 naskah arsip & 786 SNI PUPR (8.589 pecahan data) terverifikasi valid dan siap dioperasikan.

• Pemanen Data: lib/ojs.ts (skrip harvester OAI-PMH siap menyerap feed XML OJS).
• Korpus AI: Direktori data/seed (210 naskah arsip Puskim + 786 SNI PUPR terindeks).
• Layanan Dev: Port 3001 aktif melayani tanya-jawab semantik secara mandiri di server lokal.

Konsep Integrasi Tri-Sistem OJS Jurnal Permukiman • MQC Assistant • JP-Insight

Arsitektur Ekosistem & Usulan Alur Integrasi Tri-Sistem

Membangun ekosistem penerbitan ilmiah tertutup (closed-loop) yang mempercepat pemeriksaan format tanpa mengurangi wewenang substansi Dewan Redaksi, serta menghubungkan publikasi dengan repositori kecerdasan buatan:

Sistem Utama Publikasi Resmi
1. OJS Jurnal Permukiman

Pusat publikasi ilmiah Kementerian PU. Mengelola registrasi naskah, proses telaah sejawat (peer review), dan penerbitan edisi berkala.

Peran Integrasi:
• Menampung naskah terstandar & menyajikan feed metadata XML OAI-PMH terbuka.
Pemeriksaan Awal Next.js 16
2. MQC (Pengecekan Format Otomatis)

Memeriksa kesesuaian format Word (.docx) naskah masuk: gaya selingkung PUPR, margin, jenis font, struktur naskah, serta validasi sitasi.

Peran Integrasi:
• Gerbang verifikasi format mandiri & penerbitan Tiket Validasi sebelum naskah masuk ke OJS.
Pusat Referensi AI Korpus
3. JP-Insight (Sistem AI)

Sistem temu kembali cerdas berbasis AI. Menyediakan analisis kebaruan riset berdasarkan 210 arsip terbitan dan 786 regulasi SNI PUPR.

Peran Integrasi:
• Menyerap artikel terbitan OJS secara otomatis via skrip pemanen OAI-PMH tanpa unggah manual.
Alur Kerja Terpadu

Usulan Alur Proses Integrasi End-to-End (5 Tahapan)

Siklus Ekosistem Tertutup (Closed-Loop)

Alur kerja mengintegrasikan ketiga aplikasi secara harmonis mulai dari penyusunan draf oleh penulis, verifikasi format otomatis, telaah substansi oleh dewan editor, hingga pemanenan kembali ke korpus AI:

01 Penulis
Eksplorasi Sitasi & Regulasi SNI

Penulis berkonsultasi dengan JP-Insight untuk menelusuri 210 naskah arsip Puskim dan 786 SNI PUPR.

🎯 Hasil: Draf naskah memiliki referensi SNI yang kokoh sejak awal.
02 Portal MQC
Pengecekan Format Otomatis Mandiri

Penulis mengunggah berkas .docx ke MQC Assistant untuk menguji 25 kriteria gaya selingkung.

🎯 Hasil: Revisi mandiri & penerbitan Tiket Validasi Format.
03 Portal OJS
Pengajuan Naskah Terstandar

Penulis submit ke OJS menyertakan Tiket Validasi Format. OJS memverifikasi tiket via API lokal.

🎯 Hasil: Naskah masuk ke OJS dalam kondisi format 100% bersih.
04 Redaksi
Telaah Substansi Ilmiah Murni

Wewenang Redaksi Utuh: Dewan Editor & Reviewer murni menilai mutu sains, metodologi, dan signifikansi.

🎯 Hasil: Beban mekanis editor hilang, naskah disetujui & terbit resmi.
05 AI Ingest
Pemanenan Otomatis Edisi Baru

OJS menyiarkan terbitan via OAI-PMH. Skrip JP-Insight menyerap artikel baru secara otomatis ke korpus AI.

🎯 Hasil: Korpus cerdas terbarui otomatis tanpa staf mengunggah PDF.
Protokol Komunikasi

Usulan 3 Jalur Teknis Integrasi Antar-Aplikasi

Diuji di Lingkungan Uji (Server Dev)
J1 MQC ➔ OJS (Verifikasi Format)

Penulis mengecek draf naskah Word (.docx) di portal MQC. Naskah yang memenuhi aturan gaya selingkung PUPR menerbitkan Tiket Validasi Format Digital. Saat naskah diajukan ke OJS, form submission memverifikasi tiket via API lokal (/api/check-submission) sehingga naskah yang masuk ke dewan editor dijamin rapi.

API Tiket Format & Berkas Naskah Terstandar
J2 OJS ➔ JP-Insight (Automated Ingest)

OJS menyediakan feed XML resmi via protokol standar OAI-PMH v2.0 (/index.php/JP/oai). Modul lib/ojs.ts di JP-Insight secara terjadwal menyerap artikel edisi baru, mengekstrak teks, dan memasukkannya ke basis data vektor tanpa staf pengelola mengunggah PDF manual.

Protokol Terbuka OAI-PMH Harvester
J3 JP-Insight ➔ Penulis (Sitasi SNI PUPR)

Penulis memanfaatkan asisten JP-Insight untuk mencari naskah terkait terdahulu dan peraturan SNI PUPR yang relevan. Naskah yang disusun memiliki rujukan yang kuat dan langsung lolos verifikasi sitasi saat diuji di MQC.

Rujukan 786 SNI & 210 Naskah Arsip Puskim
📄
Keamanan Penyimpanan Berkas Naskah Publikasi (/opt/unggah)

Seluruh berkas naskah PDF terbitan Jurnal Permukiman disimpan pada direktori terpisah di luar web root aplikasi (/opt/unggah). Proses pembaruan sistem OJS ke PHP 8.3 dan perancangan integrasi tri-sistem tidak mengubah, memindahkan, atau memengaruhi berkas publikasi bersejarah tersebut.

Prosedur Pemulihan Cadangan (Rollback < 15 Menit)

Sebagai bentuk kepatuhan terhadap tata kelola TI yang baik, setiap tindakan pada server produksi wajib dilengkapi prosedur pemulihan seketika. Apabila terjadi kendala teknis tak terduga saat jendela jeda pemeliharaan di Server Produksi:

Langkah 1
Batas Waktu Keputusan (Menit ke-45)

Jika dalam 45 menit pertama ditemukan kendala tak terduga, tim langsung beralih ke prosedur pemulihan.

Langkah 2
Pemulihan dari Cadangan

Seluruh kode program dan basis data dikembalikan menggunakan salinan snapshot cadangan yang dibuat sebelum migrasi.

Langkah 3
Sistem Aktif Normal (< 15 Menit)

Dalam waktu kurang dari 15 menit, web Jurnal Permukiman kembali beroperasi normal tanpa risiko kehilangan data.
