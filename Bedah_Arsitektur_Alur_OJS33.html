Mengapa OJS Bukan Sekadar CMS Biasa?

Banyak yang keliru mengira OJS adalah blog artikel layaknya WordPress atau Drupal. Padahal secara arsitektur, OJS adalah Enterprise Business Process Management (BPM) & Document Lifecycle Engine yang dirancang ketat untuk menjamin integritas ilmiah, audit trail naskah, dan kepatuhan indeksasi global (Scopus, DOAJ, CrossRef).

Core Identity
PKP OJS 3.3 LTS

Dirilis oleh Public Knowledge Project (Simon Fraser University, Kanada).

Double-Blind Peer Review

Memisahkan identitas antara Penulis (Author) dan Pengulas (Reviewer) secara sistemik. File naskah diverifikasi agar bersih dari jejak identitas (metadata author/anonymized).

Versioning Submissions (OJS 3.2+)

Satu naskah (submission) memiliki banyak versi publikasi (publication). Memungkinkan revisi pasca-terbit (corrigendum) tanpa merusak integritas kutipan DOI lama.

OAI-PMH & Global Harvester

Menyediakan protokol pertukaran metadata otomatis via endpoint /oai. Mesin pengindeks (Scopus, Google Scholar, SINTA) menyedot metadata artikel secara independen.

Workflow Engine

The 5-Stage Publishing Lifecycle

Setiap naskah yang masuk tidak langsung dipublikasikan. OJS memaksa naskah bergerak melalui 5 tahapan berurutan (*stages*). Di setiap gerbang stage ada izin peran dan aksi validasi khusus.

Stage 1 WORKFLOW_STAGE_ID_SUBMISSION (1)

1. Submission (Pengajuan Awal)

Penulis mengisi 5 langkah wizard: Checklist persetujuan etika, upload file mentah (Word .docx), metadata judul/abstrak/kata kunci, co-authors, dan konfirmasi akhir.

Titik Kritis Plugin MQC: Plugin MQC mencegat file Word di stage ini untuk memastikan naskah memenuhi 22–27 aturan format penulisan Jurnal Permukiman sebelum diteruskan ke meja Editor.
Stage 2 WORKFLOW_STAGE_ID_EXTERNAL_REVIEW (3)

2. External Review (Penilaian Mitra Bestari)

Editor menugaskan 2 atau lebih reviewer independen. Reviewer membaca naskah tanpa mengetahui nama penulis (Double Blind). Hasil evaluasi bisa berupa: Accept Submission, Revisions Required (butuh perbaikan minor/mayor), Resubmit for Review (buka Round 2), atau Decline (tolak).

Stage 3 WORKFLOW_STAGE_ID_EDITING (4)

3. Copyediting (Penyuntingan Tata Bahasa)

Naskah yang sudah diterima secara substansi diperbaiki gaya bahasanya. Copyeditor memastikan kejelasan kalimat, kepatuhan referensi terhadap standar internasional (Mendeley/Zotero), dan kesesuaian gambar/tabel.

Stage 4 WORKFLOW_STAGE_ID_PRODUCTION (5)

4. Production (Pembuatan Galley Cetak)

Layout Editor mengonversi naskah final menjadi file terbitan publik (Galley PDF). Naskah diberi nomor halaman final, header volume jurnal, dan barcode/DOI. Author melakukan proofreading terakhir.

Stage 5 PUBLICATION & INDEXING

5. Publication & Terbitan Terjadwal

Editor in Chief menjadwalkan artikel ke dalam Edisi (Issue), misalnya Vol. 21 No. 1 (2026). Saat edisi diterbitkan (*Publish Issue*), DOI CrossRef diaktifkan dan metadata naskah disebarkan secara otomatis ke pangkalan data global melalui OAI-PMH.

Access Control

Matriks Peran & Hak Akses (RBAC OJS 3.3)

OJS menerapkan sistem keamanan bertingkat Role-Based Access Control (RBAC). Satu akun pengguna (users) bisa memiliki banyak peran (user_groups) sekaligus di berbagai jurnal.

Role ID Nama Peran Cakupan Wewenang Stage yang Diakses

16 Journal Manager Manajer jurnal: mengatur kebijakan (*Settings*), plugin, tema, block sidebar, anggota dewan editor, dan setup terbitan. Semua Stage & Dashboard Admin
17 Editor in Chief / Section Editor Pengambil keputusan utama: desk reject, memilih reviewer, memutuskan revisi atau penerimaan artikel, dan menyetujui publikasi. Stage 1, 2, 3, 4, 5

Source Code Architecture

Dwi-Lapisan: PKP Core Framework vs OJS Application

OJS dibangun di atas fondasi dwi-lapisan. Framework generic diletakkan di lib/pkp, sedangkan logika bisnis spesifik publikasi jurnal ada di root repository.

STRUKTUR DIREKTORI UTAMA C:\...\jurnalpermukiman 
├── classes/          # Logika domain OJS (Issue, Article, Galley)
│   ├── article/      # AuthorDAO, SubmissionDAO
│   ├── issue/        # IssueDAO, IssueAction
│   └── journal/      # JournalDAO, SectionDAO
├── controllers/      # Grid UI & Modals khusus OJS
├── pages/            # Routing URL Frontend & Dashboard
│   ├── article/      # ArticleHandler.inc.php
│   ├── issue/        # IssueHandler.inc.php
│   └── workflow/     # WorkflowHandler.inc.php
├── plugins/          # Ekosistem Ekstensi (MQC, Themes, Blocks)
│   ├── generic/      # Custom Block, MQC, ORCID, Citation
│   ├── themes/       # default, classic, bootstrap3
│   └── importexport/ # CrossRef, DOAJ, PubMed
├── templates/        # Template Smarty (.tpl) tampilan frontend
└── lib/pkp/          # 🌟 CORE ENGINE FRAMEWORK (PKP)
    ├── classes/      # Security, Session, DB, I18n, Core
    ├── controllers/  # Data Tables, File Upload Modals
    └── lib/vendor/   # ADOdb, Smarty 3, Composer dependencies

Pola Resolusi URL OJS:

index.php / {contextPath} / {page} / {op} / {args}

1. Context: JP ➔ Membaca ID Jurnal di tabel journals.path = 'JP'.

2. Page: article ➔ Memuat controller di pages/article/index.php.

3. Op: view ➔ Menjalankan method ArticleHandler::view($args, $request).

4. Args: 371 ➔ Parameter ID artikel yang akan ditampilkan ke Smarty template.

Arsitektur Hook System (Event-Driven):

OJS tidak mengharuskan developer mengubah source code core untuk menambahkan fitur baru. Semua interaksi plugin bekerja melalui hook registry: 

// Pendaftaran Event Hook oleh Plugin
HookRegistry::register('FileManager::uploadFile', array($this, 'validateWordFormat'));

// Pemicu Event di Core OJS
HookRegistry::call('FileManager::uploadFile', array(&$file, &$result));

Custom Extension Deep Dive

Titik Integrasi Plugin MQC (Manuscript Quality Control)

Bagaimana plugin MQC bekerja secara non-invasif mencegat naskah Word (.docx) di Jurnal Permukiman tanpa merusak sistem core OJS.

1

Intersepsi Upload Word

Saat Author mengunggah dokumen di Step 2 Submission, hook MQC aktif otomatis mengambil file .docx.

2

XML Parser & Rule Engine

MQC membedah arsip ZIP docx, membaca word/document.xml, dan menguji 22–27 aturan format selingkung (Font, Margin, Spasi, Abstrak, Sitasi).

3

Skor Kelayakan & Feedback

Menghasilkan laporan kepatuhan otomatis bagi Penulis dan Editor: apakah naskah siap masuk ke Stage 2 atau harus direvisi formatnya terlebih dahulu.

CONTOH PENDAFTARAN HOOK MQC DI OJS (GenericPlugin) 
class MQCPlugin extends GenericPlugin {
    public function register($category, $path, $mainContextId = null) {
        if (parent::register($category, $path, $mainContextId)) {
            if ($this->getEnabled($mainContextId)) {
                // Mencegat saat file submission selesai diupload
                HookRegistry::register('SubmissionFile::uploadFile', array($this, 'handleDocxAnalysis'));
                
                // Menyisipkan panel skor MQC ke halaman workflow Editor
                HookRegistry::register('Template::Workflow', array($this, 'injectMQCDashboard'));
            }
            return true;
        }
        return false;
    }
}
